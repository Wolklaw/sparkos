# Spark Clock

Alarms, timers, a stopwatch and world clocks (Montréal first). Alarms and timers ring with the window closed and after a restart, because a small background service rings them, not the window.

It is an optional Spark app ([brief](../../briefs/spark-clock.md)): not in the SparkOS image, installed per user without root, from Spark Store or with `install.sh --user`.

It follows the PC's language: French (Québec) when the system language is French, English otherwise; `SPARK_LANG=fr` or `SPARK_LANG=en` picks one for a single run.

## What it does

- **Alarms:** a time, the days of the week (or once), a label, a sound and a snooze length (5, 9, 10 or 15 minutes). A one-time alarm turns itself off after it rings.
- **Timers:** several at once, with a label each. Presets are buttons (1, 3, 5, 10, 15, 30 minutes; add or remove your own). A finished timer offers Stop and +1 min.
- **Stopwatch:** start, stop, laps, reset. It keeps counting if you close the window.
- **World clocks:** Montréal first, then any city you add (search by city or type a zone like `Europe/Paris`).
- **Ringing:** a desktop notification with **Stop** and **Snooze** (or **+1 min** for a timer), and a looping sound through PipeWire. Dismissing the notification stops the ring. If the window is open it shows the same buttons.
- **Command line:** `spark-clock --timer 5m --label Tea` starts a timer without opening the window (`90`, `5m`, `1h30m` and `1:30` all work).

## How alarms ring with the window closed

The window only edits files. `spark-clock --daemon` runs as a systemd user service (`spark-clock.service`), checks the time every second, and rings through the desktop's notification service and `pw-play`. `install.sh --user` turns it on, and it starts at every login. If it is off, the window says so and has a TURN ON button.

- Your data is in `~/.config/spark-clock/clock.json` (alarms, world clocks, settings) and `~/.local/state/spark-clock/` (running timers, stopwatch, the service's notes). Writes are atomic.
- Timers use real time, so one set for 20 minutes ends 20 minutes later even across a restart.
- Alarms use the PC's local time, so 07:30 stays 07:30 when the clocks change.

### After a reboot or a sleep

The service writes down the last moment it was awake. When it starts again, an alarm or timer that came due while it was off still rings if it is **less than 10 minutes late**, and says how late. Anything older shows a "missed" notice instead of ringing hours later.

### Waking the PC from sleep (version 0.2.0)

Turn on **Wake the PC from sleep** under the alarm list. The service then keeps one wake time, a minute before the next enabled alarm (or waiting snooze), and moves it whenever alarms change and after each ring. Once the PC has woken it moves the wake time to the alarm itself, in case the PC dozes off again.

- It wakes a **sleeping (suspended)** PC. It cannot turn on a PC that is shut down, and some PCs do not wake from hibernate. Whether your firmware honours the RTC alarm is not something the app can check.
- Setting a wake time needs root, so the image ships a small helper, `/usr/libexec/spark-clock-wake`, and a polkit action (`dev.wolklaw.SparkClock.wake`). The helper can only set or clear one systemd timer with `WakeSystem=true` named after the caller (`spark-clock-wake-<uid>`), for a plain epoch between 10 seconds and 8 days away. It runs nothing else, takes the user from pkexec, not from its arguments, and the person at the PC needs no password. The helper is not in the live-update bundle (root code only comes from the image), which is why this version raises `system_api` to 2.
- On an image without the helper the option says it is not available and alarms behave as before: if the PC is asleep at 07:00 the alarm rings when the PC wakes, if that is within 10 minutes, and is shown as missed after that.
- Only alarms and snoozes wake the PC. Timers do not.

## Sounds

Five alarm sounds (Beacon, Pulse, Chime, Drift, Static) are generated by `make_sounds.py` from sine waves and noise with a fixed seed. They are original to this project, so there is no third-party licence to keep (nothing is in THIRD-PARTY.md because nothing is third-party). You can also pick any `.wav`, `.ogg`, `.mp3`, `.flac` or `.opus` file from your own drives.

The player is `pw-play`; `paplay`, `gst-play-1.0` and `ffplay` are used if it is missing.

## Install

```
bash install.sh --user            # no root; starts the service
bash install.sh --user --uninstall  # stops the service, removes what it installed
spark-clock --self-test           # checks the install, touches none of your alarms
```

Without root the install is `~/.local/lib/spark-clock`, `~/.local/bin/spark-clock`, a menu entry, icons and `~/.config/systemd/user/spark-clock.service`. Uninstall keeps your alarms and the log. System-wide (`sudo bash install.sh --deps`) puts the unit in `/usr/lib/systemd/user`; each user then runs `systemctl --user enable --now spark-clock.service` once, or presses TURN ON in the window.

Needs Python 3.9 or newer with tkinter and python3-gobject (both in the SparkOS image).

## Tests

```
cd files/spark-clock
python3 -m unittest discover -s tests -v
SPARK_LANG=fr python3 -m unittest discover -s tests -v   # French, with the text-fit checks
```

The engine, schedule, store and sound loop are tested with a fake clock, notifier and player (no real sound, no D-Bus). The window tests need a display (CI uses Xvfb) and never start the service. The real notification and sound path is not covered by CI; it was tried by hand on a SparkOS PC (see the PR).

Colours, fonts and the magenta/cyan channel slip follow the Wolklaw house style. An alarm or timer going off is an event: the window tears, then settles. `SPARK_CLOCK_REDUCED_MOTION=1`, or the desktop's reduced-motion setting, turns the motion off.
